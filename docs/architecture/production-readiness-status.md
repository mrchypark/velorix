# Production Readiness Status Matrix

Reviewed on 2026-05-05 for the Velorix 1.0 production-readiness track.

This matrix separates current bootstrap evidence from 1.0 required evidence.
It summarizes the architecture document set; it is not an implementation audit
or a claim that Velorix is production-ready today.

Status values are limited to `complete`, `partial`, and `missing`.

| Contract | Current Evidence | 1.0 Required Evidence | Status | Blocking Tasks |
| --- | --- | --- | --- | --- |
| ingest | `storage-contract.md` defines durable object-store acknowledgement semantics and stable `v1/ingest` keys; `ingest-envelope-v1.md`, `ingest-admission-contract.md`, and `ingest-storage-format-decision.md` define the Arrow IPC envelope, digest, and admission rules. Current docs still identify JSON `DeltaBatch` replay as bootstrap-only. | Deterministic Arrow IPC envelope framing, corruption checks, durable idempotency/range-admission evidence, and removal or explicit migration gating for JSON `DeltaBatch` production paths. | partial | Implement Arrow envelope framing and tests; add coordinated range admission or write coordinator before multi-writer overlap guarantees; remove production reliance on JSON `DeltaBatch`. |
| relation catalog | `relation-contract-v1.md` defines create-only `v1/relations/{relation_id}/versions/{relation_version}.relation.json`, schema fingerprints, DataFusion registration, Feldera validation, and incremental adapter identity. | Verified relation catalog storage, relation-version pinning, typed DataFusion registration, Feldera artifact fingerprint rejection, and replay through typed relation batches. | partial | Implement catalog-backed relation activation and cross-surface tests proving ingest, DataFusion, Feldera metadata, and incremental input use the same relation identity. |
| object-store capability | `object-store-capabilities-v1.md` defines `AuthoritativeObjectStoreCapabilitiesV1`, required namespaces, fail-closed startup, shared registry, and dev/local fallback limits. Current code validates declared namespace profiles and requires capability-backed registry entries for production table scans. | Production startup probes for every authoritative namespace, rejection of overwrite-only/local emulation in production, diagnostics, and shared registry evidence for storage, DataFusion, SlateDB, and Foyer. | partial | Implement runtime capability probing and shared registry enforcement beyond production table scans; add fake-backend rejection tests and S3-compatible capability evidence. |
| ownership | `partition-ownership-protocol-v1.md` and `storage-contract.md` define object-backed epoch records, owner claims on state/output/manifest writes, stale-owner checks, and the Kubernetes Lease coordination boundary. | Durable epoch-record creation after lease acquisition, production rejection of claims without epoch records, stale-worker rejection after lease loss, and real Kubernetes or equivalent lease adapter evidence. | partial | Add Kubernetes lease implementation, durable epoch record validation, and production-mode tests rejecting fake/in-memory leases and stale writers. |
| checkpoint lifecycle | `storage-contract.md` defines checkpoint manifests as durable authority and `checkpoint-recovery-index-v1.md` defines latest-candidate validation and recovery modes; `package-review-index.md` calls out missing lifecycle statuses and cleanup. | Explicit checkpoint lifecycle records or statuses, retention metadata, recovery transitions, compaction/cleanup integration, and admin inspection evidence beyond latest-manifest lookup. | partial | Implement checkpoint lifecycle status records, retention policy, admin inspection, and recovery transition tests. |
| state substrate | `state-substrate-contract.md` defines raw bootstrap refs versus `SlateDbCheckpointRefV1`, requires typed state refs, and forbids Velorix GC prefix-walking SlateDB internals. | Production manifests recover from SlateDB checkpoint/root handles, raw state refs are rejected without bootstrap or migration flag, mixed raw-to-SlateDB lineage is explicit and tested, and GC uses SlateDB-owned retention handles. | partial | Implement tagged state references, SlateDB handle recovery, production raw-ref rejection, and GC integration through SlateDB-owned APIs. |
| DataFusion policy | `datafusion-resource-policy-v1.md` defines `QueryExecutionPolicyV1`, typed errors, timeout, memory, spill, scan-byte, object-request, file, and concurrency limits. | table registry | `external-table-surface-contract.md` and `storage-contract.md` define registry-backed production table specs under `v1/tables` and reject raw `s3://`, `http://`, and `file://` URL authority in production. | Allowlisted object-store registry identity, tenant prefix policy, query policy linkage, raw URL rejection in production, and bounded DataFusion scans through the shared registry. | partial | Finish registry-backed table lookup, production raw URL rejection, tenant prefix validation, and scan-limit tests. |
| Feldera artifact registry | `feldera-artifact-contract.md` defines `StandingViewSpec`, `FelderaCompileArtifactMetadata`, spec hashes, fail-closed validation, relation fingerprint checks, and the release artifact trust boundary. | Persisted release artifact registry mapping artifact id/hash to trusted compiled packages, build/release verification, runtime artifact selection, and state/resource/recovery gates before direct execution. | partial | Implement persisted artifact registry and release verification path; keep runtime Feldera/DBSP execution gated until artifact, state, resource, and recovery contracts are proven. |

| S3-compatible tests | `benchmark-gate-v1.md`, `object-store-capabilities-v1.md`, `storage-contract.md`, and package reviews require S3-compatible evidence and say local filesystem emulation is not production evidence. | Env-gated S3-compatible integration tests for capability probes, ingest, checkpoint publication/recovery, DataFusion scans, benchmark artifacts, and failure modes. | missing | Add S3-compatible test suite and CI/nightly configuration with explicit credentials/backend gating. |

| GC | `storage-contract.md` says current bootstrap only classifies recoverable garbage and does not implement production GC; `state-substrate-contract.md` forbids deleting SlateDB internals by prefix walk. | Manifest-aware mark/sweep planning, retention policy, staging-object safety, listing-consistency behavior, and SlateDB-safe deletion through owned handles or APIs. | missing | Implement GC plan/execute paths, live-manifest retention tests, staging-attempt safety tests, and SlateDB internal-prefix rejection tests. |
| dependency governance | `package-review-index.md` and `package-review-feldera-and-core-packages.md` require version pinning, MSRV, license, advisory, feature-flag, audit, replacement-plan, and upgrade-test governance; `benchmark-gate-v1.md` requires CI-facing gates. | `cargo deny` or equivalent license/advisory policy, dependency audit/vet process, feature-flag review, MSRV policy, replacement plans for gated packages, and CI enforcement. | missing | Add `deny.toml`, CI dependency governance checks, and documented package review/audit workflow. |
