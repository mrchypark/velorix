# Production Readiness Status Matrix

Reviewed on 2026-05-05 for the Velorix 1.0 production-readiness track.

This matrix separates current bootstrap evidence from 1.0 required evidence.
It summarizes the architecture document set; it is not an implementation audit
or a claim that Velorix is production-ready today.

Status values are limited to `complete`, `partial`, and `missing`.

| Contract | Current Evidence | 1.0 Required Evidence | Status | Blocking Tasks |
| --- | --- | --- | --- | --- |
| ingest | `storage-contract.md` defines durable object-store acknowledgement semantics and stable `v1/ingest` keys; `ingest-envelope-v1.md`, `ingest-admission-contract.md`, and `ingest-storage-format-decision.md` define the Arrow IPC envelope, digest, and admission rules. Current runtime replay uses validated Arrow ingest envelopes and rejects legacy JSON `DeltaBatch` bytes under `v1/ingest`; JSON `DeltaBatch` remains only as bootstrap/internal checkpoint-state compatibility and prototype scaffolding. | Deterministic Arrow IPC envelope framing, corruption checks, durable idempotency/range-admission evidence, and removal or explicit migration gating for JSON `DeltaBatch` production paths. | partial | Add coordinated range admission or write coordinator before multi-writer overlap guarantees; keep durable ingest replay envelope-only and prevent new JSON `DeltaBatch` durable ingest paths. |
| relation catalog | `relation-contract-v1.md` defines create-only `v1/relations/{relation_id}/versions/{relation_version}.relation.json`, schema fingerprints, DataFusion registration, Feldera validation, and incremental adapter identity. `crates/velorix-storage` persists and reads validated catalog objects by `(relation_id, relation_version)` with idempotent duplicate creates, same-key conflict rejection, stored-body identity checks, strict stored JSON parsing, and durable object-store capability gating. Current code also derives typed DataFusion schemas/registration and Feldera input schemas from the catalog, rejects ingest relation-id/version/fingerprint mismatches during recovery, and tests ingest/DataFusion/Feldera identity alignment. | Relation-version pinning, typed DataFusion registration, Feldera artifact fingerprint rejection, and replay through typed relation batches all backed by the cataloged relation identity. | partial | Finish typed incremental-input adapter integration and any remaining production wiring that still bypasses catalog-backed helpers. |
| object-store capability | `object-store-capabilities-v1.md` defines `AuthoritativeObjectStoreCapabilitiesV1`, required namespaces, fail-closed startup, shared registry, and dev/local fallback limits. Current code validates declared namespace profiles, including relation catalog, exposes per-namespace backend/missing-capability diagnostics, requires capability-backed registry entries for production table scans, and has runtime probes that build an `AuthoritativeObjectStoreCapabilitiesV1` by checking create-only, read-after-write, list-after-write, and complete-payload visibility for every authoritative namespace. The runtime storage registry can now register a production DataFusion scan store only after probing a Velorix authority object store, which keeps the current DataFusion `object_store` version boundary explicit. Tests reject a fake backend that silently overwrites `PutMode::Create` requests and report the failing namespace. | Production startup probes for every authoritative namespace, rejection of overwrite-only/local emulation in production, diagnostics, and shared registry evidence for storage, DataFusion, SlateDB, and Foyer. | partial | Wire the probed registry path into deployment/operator startup, extend shared registry enforcement beyond production table scans, and add S3-compatible capability evidence for each authoritative namespace. |
| ownership | `partition-ownership-protocol-v1.md` and `storage-contract.md` define object-backed epoch records, owner claims on state/output/manifest writes, stale-owner checks, and the Kubernetes Lease coordination boundary. Current code has storage-side durable epoch record checks, a pure fail-closed production ownership backend gate that rejects in-memory/dev leases and missing durable epoch record support, and a `velorix-k8s` Kubernetes Lease adapter with fake-client tests for acquire, renew, read, release, holder mismatch, stale epoch, invalid Lease bodies, mismatched returned Lease keys, and update conflicts. The adapter persists lease-derived `OwnershipEpochRecord` values through the storage create-only API while keeping production publication gated on the durable record. | Durable epoch-record creation after lease acquisition, production rejection of claims without epoch records, stale-worker rejection after lease loss, and real Kubernetes or equivalent lease adapter evidence. | partial | Add stale-writer evidence after lease loss, integrate the helper into the worker/operator path, and add env-gated live Kubernetes evidence. |
| checkpoint lifecycle | `storage-contract.md` defines checkpoint manifests as durable authority; `checkpoint-recovery-index-v1.md` defines latest-candidate validation, recovery modes, digest-bound `published` lifecycle status records, and admin inspection. Current code writes readable published lifecycle records, can inspect manifests to report invalid future checkpoints while preserving the latest valid checkpoint for repair/read-only diagnosis, and exposes read-only local checkpoint inspection through `velorix-cli checkpoint-inspect-local`. | Lifecycle transitions beyond `published`, retention metadata that affects GC, recovery transition records, compaction/cleanup integration, and admin repair/read-only recovery commands. | partial | Add lifecycle transitions beyond `published`, retention tombstones/policy enforcement, compaction/cleanup state, and admin repair/read-only recovery commands. |
| state substrate | `state-substrate-contract.md` defines raw bootstrap refs versus `SlateDbCheckpointRefV1`, requires typed state refs, and forbids Velorix GC prefix-walking SlateDB internals. Current code writes optional SlateDB checkpoint metadata with database path, state key, SHA-256 digest, byte length, and creating checkpoint version; publication validates a small same-transaction SlateDB marker and payload-key readability without hashing full payloads on the publish path; SlateDB reads fail closed for raw refs, missing or mismatched metadata, digest/length mismatch, and can recover after close/reopen through the returned ref. Production fenced publication rejects raw refs. | Production manifests recover from SlateDB checkpoint/root handles, raw state refs are rejected without bootstrap or migration flag, mixed raw-to-SlateDB lineage is explicit and tested, and GC uses SlateDB-owned retention handles. | partial | Finish SlateDB retention/release through SlateDB-owned APIs, make mixed raw-to-SlateDB lineage explicit where migration needs it, and extend recovery evidence beyond the current narrow state-byte handle. |
| DataFusion policy | `datafusion-resource-policy-v1.md` defines `QueryExecutionPolicyV1`, typed errors, timeout, memory, spill, scan-byte, object-request, file, and concurrency limits. Runtime query paths now centralize DataFusion `SessionContext` creation and wire `batch_size`, `target_partitions`, `memory_limit_bytes`, and `spill_limit_bytes` through DataFusion 53 `SessionConfig`/`RuntimeEnvBuilder`; timeout, output byte, scan preflight, query-wide object-request metering, and concurrency evidence exists in runtime tests. | Policy connected to DataFusion session config, memory/spill/cancellation, exact object-store scan instrumentation, planning/execution timeouts, output byte limits, and concurrency pools, with clear evidence for DataFusion-version-dependent memory/spill behavior. | partial | Add version-specific memory/spill failure evidence only where DataFusion reliably enforces it; finish cancellation and tenant/global shared-runtime semantics. |
| table registry | `external-table-surface-contract.md` and `storage-contract.md` define registry-backed production table specs under `v1/tables` and reject raw `s3://`, `http://`, and `file://` URL authority in production. Current runtime code also has a create-only durable query policy catalog under `v1/query-policy/{tenant_id}/{query_policy_id}.json`; production table specs now pin `relation_id`, `relation_version`, and `schema_fingerprint`, creation rejects mismatches against the relation catalog before writing, and query rechecks the current catalog fingerprint after tenant rejection and before policy/scan resolution. | Allowlisted object-store registry identity, tenant prefix policy, query policy linkage, relation-catalog fingerprint binding, raw URL rejection in production, and bounded DataFusion scans through the shared registry. | partial | Finish any remaining production wiring that still bypasses catalog-backed table/policy helpers. |
| Feldera artifact registry | `feldera-artifact-contract.md` defines `StandingViewSpec`, `FelderaCompileArtifactMetadata`, spec hashes, fail-closed validation, relation fingerprint checks, the release artifact trust boundary, and the storage create-only metadata registry at `v1/feldera-artifacts/{artifact_id}/sha256/{artifact_hash_hex}.artifact.json`. `crates/velorix-storage` persists and reads validated metadata with idempotent duplicate creates, same-key conflict rejection, and stored-body identity checks. `crates/velorix-runtime` now exposes a thin runtime facade that validates registration/selection against a supplied `VelorixRelationCatalogV1` and returns trusted metadata with direct execution disabled, without adding a tenant/artifact-id object-key scheme. | Persisted release artifact registry mapping artifact id/hash to trusted compiled packages, build/release verification, runtime artifact selection, and state/resource/recovery gates before direct execution. | partial | Add release verification path and any future globally unique artifact-id index only if product semantics require it; keep runtime Feldera/DBSP execution gated until artifact, state, resource, and recovery contracts are proven. |
| benchmark gate | `benchmark-gate-v1.md` defines PR smoke, nightly S3-compatible, and release gates, required JSON metrics, V1 `workload_metrics`, regression budgets, and S3-compatible artifact requirements; it also says `local_incremental` is bootstrap evidence only. Current code validates benchmark JSON, including required object-request metrics and workload detail sanity checks, through `velorix-cli benchmark-validate`; `velorix-cli benchmark-gate --gate-level --backend` also requires the current V1 workload detail names. `local_incremental` now emits real local instrumentation details for ingest envelope validation, checkpoint publication, checkpoint recovery, bounded DataFusion Parquet table scan, SlateDB state write/read/reopen through public state-store APIs, and GC dry-run planning through `CheckpointPublisher::plan_garbage_collection`. The committed local/S3 baselines are conservative gate-wiring placeholders, not production performance claims; release gating rejects placeholder release baselines. | Schema-validated benchmark JSON, local and S3 baselines based on real workload evidence, synthetic regression failure tests, object request metrics, and CI/release workflows that fail closed on missing or mixed backend evidence. | partial | Replace placeholder baselines with measured local and S3-compatible evidence, implement the live S3 benchmark, add GC execution/listing-consistency evidence outside local bootstrap timing, and keep release blocked until a real S3 release baseline exists. |
| S3-compatible tests | `s3-compatible-test-harness.md` defines the live env contract and skipped-by-default behavior; `crates/velorix-storage/tests/s3_compat.rs` validates create-only conflict, read-after-write, list-after-write, range read, and best-effort cleanup against an explicitly enabled S3-compatible backend. `benches/s3_incremental.rs` now fails closed unless `VELORIX_S3_COMPAT=1` and real S3 config are present, and it refuses to emit local or synthetic benchmark JSON while the live workload is unimplemented. `benchmark-gate-v1.md`, `object-store-capabilities-v1.md`, `storage-contract.md`, and package reviews require broader S3-compatible evidence and say local filesystem emulation is not production evidence. | Env-gated S3-compatible integration tests for capability probes, ingest, checkpoint publication/recovery, DataFusion scans, benchmark artifacts, and failure modes. | partial | Extend beyond the storage-level object semantics harness into ingest, checkpoint recovery, DataFusion scans, benchmark artifacts, failure modes, and CI/nightly configuration with explicit credentials/backend gating. |
| Kubernetes operator | `package-review-index.md` and `third-party-first.md` define a Kubernetes-native production direction with CRDs, operator reconciliation, status, scheduling intent, worker orchestration, and Lease-based fencing. `crates/velorix-control` has a kube-free Kubernetes control-plane contract skeleton: stable serde wire shapes for desired view intent, observed-only status fields, and a side-effect-free reconcile plan that forbids worker start from status-only progress or lease-only ownership without a matching durable epoch record. `crates/velorix-k8s` owns the Kubernetes dependencies and generates namespaced CRD schemas for `VelorixDatabase`, `VelorixStream`, `VelorixTable`, `VelorixWorkerShard`, `VelorixCheckpointPolicy`, and `VelorixBenchmarkGate`, with tests for required spec fields and per-kind observed-only status shape. It also has a pure controller reconciliation core that validates stream authority and relation fingerprints from object-store-backed evidence and produces status-update actions only; stale Kubernetes checkpoint status is replaced by the authoritative evidence snapshot. A Kubernetes Lease adapter now uses `coordination.k8s.io/v1` Lease shapes behind a fakeable API boundary and writes lease-derived epoch records through storage create-only semantics without making Kubernetes the database authority. There is still no API status writer, watch loop, controller runtime, runtime wiring, or env-gated cluster evidence. | CRD schemas, operator reconciliation skeleton, status writer, real or env-gated Kubernetes lease adapter, and tests proving Kubernetes remains coordination-only while object storage stays authoritative. | partial | Add API status writer/watch loop, env-gated cluster tests, and worker/operator integration without making Kubernetes status authoritative. |
| GC | `storage-contract.md` now documents a deterministic manifest-aware plan/execute path for Velorix-owned raw `v1/state/...` and `v1/outputs/...` objects, retaining latest published manifests, avoiding SlateDB internal-prefix deletes, and leaving `v1/tmp/...` publish-temp attempt objects unplanned and undeleted in focused checkpoint-publish evidence. `velorix-cli gc-plan-local --json` exposes the read-only GC dry-run plan with stable `schema_version=1` JSON, and storage tests cover orphan raw state, orphan output, referenced-object retention, temp attempt exclusion, SlateDB prefix exclusion, unsafe caller-plan rejection, and stale-plan rejection when a new manifest references a candidate; `state-substrate-contract.md` still requires SlateDB-owned retention APIs for SlateDB state. | Production GC evidence for listing-consistency behavior, lifecycle/retention administration, and SlateDB-safe deletion through owned handles or APIs. | partial | Add listing-consistency behavior, lifecycle/retention administration evidence, and SlateDB retention API integration. |
