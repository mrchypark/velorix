# Production Readiness Status Matrix

Reviewed on 2026-05-05 for the Velorix 1.0 production-readiness track.

This matrix separates current bootstrap evidence from 1.0 required evidence.
It summarizes the architecture document set; it is not an implementation audit
or a claim that Velorix is production-ready today.

Status values are limited to `complete`, `partial`, and `missing`.

| Contract | Current Evidence | 1.0 Required Evidence | Status | Blocking Tasks |

| ingest | `storage-contract.md` defines durable object-store acknowledgement semantics and stable `v1/ingest` keys; `ingest-envelope-v1.md`, `ingest-admission-contract.md`, and `ingest-storage-format-decision.md` define the Arrow IPC envelope, digest, and admission rules. Current runtime replay uses validated Arrow ingest envelopes and rejects legacy JSON `DeltaBatch` bytes under `v1/ingest`; JSON `DeltaBatch` remains only as bootstrap/internal checkpoint-state compatibility and prototype scaffolding. `IngestLog::append_catalog_validated_envelope` and `append_catalog_validated_envelope_single_writer` now read the persisted relation catalog before durable append, reject missing catalogs, stale schema fingerprints, and Arrow batch schema mismatches before committing `v1/ingest` objects, and preserve idempotent same-digest retry. The local and S3-compatible benchmark harnesses plus the env-gated S3 runtime recovery harness now create the relation catalog before ingest and use the catalog-aware append path. The single-writer variant also keeps visible committed-range overlap rejection for serialized admission while multi-writer overlap guarantees remain unadvertised. | Deterministic Arrow IPC envelope framing, corruption checks, relation-catalog-backed durable admission, durable idempotency/range-admission evidence, and removal or explicit migration gating for JSON `DeltaBatch` production paths. | partial | Add coordinated range admission or write coordinator before multi-writer overlap guarantees; prevent new JSON `DeltaBatch` durable ingest paths and keep expanding production caller coverage as new ingest surfaces are added. |
| relation catalog | `relation-contract-v1.md` defines create-only `v1/relations/{relation_id}/versions/{relation_version}.relation.json`, schema fingerprints, DataFusion registration, Feldera validation, and incremental adapter identity. `crates/velorix-storage` persists and reads validated catalog objects by `(relation_id, relation_version)` with idempotent duplicate creates, same-key conflict rejection, stored-body identity checks, strict stored JSON parsing, and durable object-store capability gating. Current code also derives typed DataFusion schemas/registration and Feldera input schemas from the catalog, rejects unsafe DataFusion registration names such as `input` and qualified/reserved names, can recover by reading the catalog record before replay, rejects ingest relation-id/version/fingerprint mismatches during recovery, and tests ingest/DataFusion/Feldera identity alignment. `crates/velorix-core` now owns the minimal catalog-backed orders sum/count incremental-input adapter: it validates relation identity, adapter id, catalog Arrow schema, and non-null key/value/weight columns before converting decoded Arrow record batches to `DeltaBatch`; runtime recovery calls this helper after envelope decode instead of extracting columns itself. Production table scans now register Parquet snapshots under the catalog DataFusion table name with the catalog-derived Arrow schema instead of the bootstrap `input` table. | Relation-version pinning, typed DataFusion registration, Feldera artifact fingerprint rejection, and replay through typed relation batches all backed by the cataloged relation identity. | partial | Expand typed incremental-input adapter coverage beyond the current orders sum/count prototype and wire any remaining production callers that still bypass catalog-backed helpers. |
| object-store capability | `object-store-capabilities-v1.md` defines `AuthoritativeObjectStoreCapabilitiesV1`, required namespaces, fail-closed startup, shared registry, and dev/local fallback limits. Current code validates declared namespace profiles, including relation catalog, exposes per-namespace backend/missing-capability diagnostics, requires capability-backed registry entries for production table scans, and has runtime probes that build an `AuthoritativeObjectStoreCapabilitiesV1` by checking create-only, read-after-write, list-after-write, and complete-payload visibility for every authoritative namespace. The runtime storage registry can now register a production DataFusion scan store only after probing a Velorix authority object store, which keeps the current DataFusion `object_store` version boundary explicit. `crates/velorix-k8s` also exposes a narrow operator startup guard that probes the configured authority object store, carries the validated `AuthoritativeObjectStoreCapabilitiesV1` evidence, and gates the production relation-catalog snapshot provider constructor. | ownership | `partition-ownership-protocol-v1.md` and `storage-contract.md` define object-backed epoch records, owner claims on state/output/manifest writes, stale-owner checks, and the Kubernetes Lease coordination boundary. Current code has storage-side durable epoch record checks, a pure fail-closed production ownership backend gate that rejects in-memory/dev leases and missing durable epoch record support, and a `velorix-k8s` Kubernetes Lease adapter with fake-client tests for acquire, renew, read, release, holder mismatch, stale epoch, invalid Lease bodies, mismatched returned Lease keys, and update conflicts. The adapter persists lease-derived `OwnershipEpochRecord` values through the storage create-only API while keeping production publication gated on the durable record; runtime production publication and the worker-shard ownership bridge both reject a lower Kubernetes grant after a newer durable epoch record before allowing state/output/manifest writes or worker start. | Durable epoch-record creation after lease acquisition, production rejection of claims without epoch records, stale-worker rejection after lease loss, and real Kubernetes or equivalent lease adapter evidence. | partial | Add env-gated live Kubernetes evidence and wire the worker-shard bridge into the runtime operator loop. |
| checkpoint lifecycle | `storage-contract.md` defines checkpoint manifests as durable authority; `checkpoint-recovery-index-v1.md` defines latest-candidate validation, recovery modes, digest-bound `published` lifecycle status records, retention evidence records, and admin inspection. Current code writes readable published lifecycle records, writes digest-bound append-only checkpoint retention records after GC run evidence read-back for non-retained checkpoints whose payloads were deleted, can inspect manifests to report invalid future checkpoints while preserving the latest valid checkpoint for repair/read-only diagnosis, treats GC-deleted payloads on an older listed parent as invalid for that older manifest without invalidating a newer retained child whose own payloads remain available, exposes read-only local checkpoint inspection through `velorix-cli checkpoint-inspect-local`, and can recover read-only from an admin-selected published checkpoint version after validating the manifest body/key/version, parent lineage, payload visibility, and matching lifecycle digest. Local admin recovery can open SlateDB-backed checkpoint state with `velorix-cli recover-local --slatedb-state-path <object-store-db-path> --checkpoint-version <n>`, where the SlateDB path is the object-store database path, not another local root. | Lifecycle transitions beyond `published`, retention metadata that affects GC, recovery transition records, compaction/cleanup integration, and admin repair/read-only recovery commands. | partial | Add lifecycle transitions beyond `published`, compaction/cleanup state, full admin repair commands, and any manifest-deletion policy only after explicit design review. |
| state substrate | `state-substrate-contract.md` defines raw bootstrap refs versus `SlateDbCheckpointRefV1`, requires typed state refs, and forbids Velorix GC prefix-walking SlateDB internals.
