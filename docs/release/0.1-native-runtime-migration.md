# Native runtime API migration

This change intentionally removes the experimental public Rust modules
`velorix_core::{circuit, incrementalize, sql_to_circuit}` and
`velorix_{control,runtime}::{general_circuit_runtime, disk_state}`. They were
not used by the product API, had divergent checkpoint semantics, and could
admit SQL that the production materialized-view engine did not execute.

Rust consumers must migrate view admission to
`velorix_core::view_plan::lower_supported_sql_to_logical_plan` and construct or
restore runtimes through `velorix_control::materialized_view_runtime`. Durable
state remains owned by the production checkpoint and storage APIs; there is no
compatibility shim for checkpoints produced by the removed experimental
runtime.

Velorix is still on the pre-release `0.1` line, so this is an intentional
breaking cleanup before a stable crate API. The supported SQL contract is
documented in [supported-sql.md](../architecture/supported-sql.md).
