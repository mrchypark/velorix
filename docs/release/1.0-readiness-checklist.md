# Velorix 1.0 Release Readiness Checklist

Status: **not ready**.

Velorix 1.0 is blocked until every row in
`docs/architecture/production-readiness-status.md` is present and has status
`complete`. Any `partial` row, `missing` row, absent required row, missing
verification command, or missing evidence artifact keeps the release blocked.

## Required Status Rows

The architecture status matrix must contain exactly these 1.0 contracts:

- ingest
- relation catalog
- object-store capability
- ownership
- checkpoint lifecycle
- state substrate
- DataFusion policy
- table registry
- Feldera artifact registry
- benchmark gate
- S3-compatible tests
- Kubernetes operator
- GC
- dependency governance

Current status source:
`docs/architecture/production-readiness-status.md`.

Current release decision: blocked, because the status matrix still contains
`partial` rows.

## Verification Gate

All command-backed gates below must pass for the same candidate commit. Record
the command, exit status, timestamp, environment flags, and artifact path or log
path.

| Gate | Required Command | Required Evidence |
| --- | --- | --- |
| Formatting | `cargo fmt --all -- --check` | Passing command log. |
| Lints | `cargo clippy --workspace --all-targets -- -D warnings` | Passing command log. |
| Workspace tests | `cargo test --workspace` | Passing command log. |
| Dependency governance | `cargo deny check -W unmaintained` and `cargo run -p velorix-cli -- dependency-governance-validate --manifest dependency-governance.json` | Passing command logs, with declared warning-only exceptions tracked by owner, expiry, and reason. |
| Readiness report | `cargo run -p velorix-cli -- readiness-report --evidence <evidence-json> --json` | JSON output with `production_ready=true`. |
| S3-compatible storage harness | `VELORIX_S3_COMPAT=1 cargo test -p velorix-storage --test s3_compat --features s3-compat-tests` | Passing log with backend, bucket, prefix, and credential source redacted. |
| S3-compatible query harness | `VELORIX_S3_COMPAT=1 cargo test -p velorix-runtime --test s3_compat_query --features s3-compat-tests` | Passing log with backend, bucket, prefix, and credential source redacted. |
| S3-compatible benchmark | `VELORIX_S3_COMPAT=1 cargo bench -p velorix-runtime --bench s3_incremental` | Benchmark JSON artifact from a live S3-compatible backend. |
| CRD schema generation | `cargo test -p velorix-k8s` | Passing log and generated schema artifact path if emitted. |
| Benchmark PR smoke | `cargo run -p velorix-cli -- benchmark-gate --gate-level pr-smoke --backend local --baseline baselines/benchmark/local/pr-smoke.json --result <current-json>` | Passing log and current benchmark JSON artifact. |
| Benchmark nightly S3 | `cargo run -p velorix-cli -- benchmark-gate --gate-level nightly-integration --backend s3-compatible --baseline baselines/benchmark/s3/nightly.json --result <current-json>` | Passing log and live S3-compatible benchmark JSON artifact. |
| Benchmark release S3 | `cargo run -p velorix-cli -- benchmark-gate --gate-level release --backend s3-compatible --baseline baselines/benchmark/s3/release.json --result <current-json>` | Passing log and live S3-compatible release benchmark JSON artifact. |
| GC dry-run | `cargo run -p velorix-cli -- gc-plan-local --object-store-dir <dir> --retain-latest-manifests <n> --json` | Stable `schema_version=1` JSON plan artifact with no deletion executed. |
| GC local/admin execution | `cargo run -p velorix-cli -- gc-execute-local --object-store-dir <dir> --retain-latest-manifests <n> --run-id <id> --json` | Stable `GcRunV1` JSON artifact written under `v1/gc-runs/...`; local/admin evidence only. |

## Known Blocked Gates

These are required before 1.0, but this repository does not yet expose an
executable release command for them:

- Kubernetes Lease integration: needs an env-gated live cluster command and
  passing log naming the target cluster/context with secrets redacted.
- GC production execution: needs a production GC execution command for the
  target backend and a `GcRunV1` JSON artifact with retained-manifest evidence.

## Fail-Closed Rule

Do not mark 1.0 ready unless all of these checks are true:

- `docs/architecture/production-readiness-status.md` has no `partial` status.
- `docs/architecture/production-readiness-status.md` has no `missing` status.
- Every required status row listed above is present.
- Every verification command above passed on the same candidate commit.
- Every evidence artifact above is recorded and reviewable.
- `cargo run -p velorix-cli -- readiness-report --evidence <evidence-json> --json` returned
  `production_ready=true`.

Suggested status check:

```bash
rg -n '\| (partial|missing) \|' docs/architecture/production-readiness-status.md
```

This command must return no matches before 1.0 can be considered ready.
