# 1.0 Readiness Checklist

Velorix 1.0 readiness is based on the jarless materialized view runtime. A
release cannot be marked ready from a static docs matrix; readiness is generated
from concrete evidence artifacts and image digests.

Required release inputs:

- production readiness evidence bound to the release commit
- S3-compatible benchmark gate evidence
- S3-compatible delayed-visibility, retry, and fault-injection checkpoint matrix
  evidence kind on `s3_compatible_test_status`
- production GC evidence
- RustFS production GC validation evidence
- upgrade/rollback/repair/GC fault-matrix evidence kind on `gc_status`
- Hiqlite no-PVC three-voter total-voter-loss live restore drill evidence:
  standalone drill artifact kind `hiqlite_total_voter_loss_restore_drill`;
  readiness compatibility evidence kind
  `hiqlite_no_pvc_three_voter_backup_restore`
- query output isolation evidence kind `query_output_isolation`
- security/release provenance evidence kind `security_release_provenance`
- remaining release-readiness evidence kind `remaining_release_readiness`
- ingest-writer lifecycle evidence
- standing-runtime product evidence
- release image digests for `velorix-api` and `velorix-meta` in the
  security/release provenance evidence; the Hiqlite authority image digest is
  bound by the separate Hiqlite backend-time trusted provenance attestation

Required release check:

```bash
cargo run -p velorix-cli -- readiness-report \
  --evidence "$READINESS_EVIDENCE_PATH" \
  --require-release-artifacts \
  --dependency-governance-evidence target/dependency-governance/local-dependency-governance-evidence.json \
  --dependency-governance-manifest dependency-governance.json \
  --release-commit "$RELEASE_COMMIT" \
  --s3-release-benchmark-gate-evidence target/release-evidence/s3-release-benchmark-gate.json \
  --production-gc-run-evidence "$PRODUCTION_GC_RELEASE_PATH" \
  --rustfs-production-gc-validation-evidence "$RUSTFS_PRODUCTION_GC_RECHECKED_PATH" \
  --ingest-writer-lifecycle-evidence "$INGEST_WRITER_LIFECYCLE_RELEASE_PATH" \
  --standing-runtime-product-evidence "$STANDING_RUNTIME_PRODUCT_RELEASE_PATH" \
  --s3-checkpoint-fault-matrix-evidence "$VELORIX_S3_CHECKPOINT_FAULT_MATRIX_EVIDENCE_PATH" \
  --hiqlite-restore-drill-evidence "$VELORIX_HIQLITE_RESTORE_DRILL_EVIDENCE_PATH" \
  --upgrade-rollback-repair-gc-fault-matrix-evidence "$VELORIX_UPGRADE_ROLLBACK_REPAIR_GC_FAULT_MATRIX_EVIDENCE_PATH" \
  --query-output-isolation-evidence "$VELORIX_QUERY_OUTPUT_ISOLATION_EVIDENCE_PATH" \
  --security-release-provenance-evidence "$VELORIX_SECURITY_RELEASE_PROVENANCE_EVIDENCE_PATH" \
  --remaining-release-readiness-evidence "$VELORIX_REMAINING_RELEASE_READINESS_EVIDENCE_PATH" \
  --json
```

The gate fails closed when a required artifact is absent, reports a failing
status, is local-only where release evidence is required, is not identity bound
to the readiness evidence, `s3_compatible_test_status.evidence_kind` lacks
`s3_compatible_checkpoint_fault_matrix`, `kubernetes_status.evidence_kind`
lacks `hiqlite_no_pvc_three_voter_backup_restore`, or the standalone Hiqlite
restore drill artifact lacks `hiqlite_total_voter_loss_restore_drill`, or
`gc_status.evidence_kind` lacks `upgrade_rollback_repair_gc_fault_matrix`.
The readiness report validates
relation catalog, object-store capability, checkpoint lifecycle, state
substrate, DataFusion policy, table registry, materialized view runtime,
benchmark, Kubernetes, GC, and dependency governance status.

Evidence-shape validators are fail-closed helpers, not evidence producers:

```bash
scripts/check-s3-checkpoint-fault-matrix-evidence.sh "$VELORIX_S3_CHECKPOINT_FAULT_MATRIX_EVIDENCE_PATH"
scripts/check-hiqlite-restore-drill-evidence.sh "$VELORIX_HIQLITE_RESTORE_DRILL_EVIDENCE_PATH"
scripts/check-upgrade-rollback-repair-gc-fault-matrix-evidence.sh "$VELORIX_UPGRADE_ROLLBACK_REPAIR_GC_FAULT_MATRIX_EVIDENCE_PATH"
scripts/check-query-output-isolation-evidence.sh "$VELORIX_QUERY_OUTPUT_ISOLATION_EVIDENCE_PATH"
scripts/check-security-release-provenance-evidence.sh "$VELORIX_SECURITY_RELEASE_PROVENANCE_EVIDENCE_PATH"
scripts/check-remaining-release-readiness-evidence.sh "$VELORIX_REMAINING_RELEASE_READINESS_EVIDENCE_PATH"
```

Every live/release evidence artifact above must be bound to the same release
identity: a concrete 40-character Velorix `source_revision` and sha256
`deployed_image_digests` for both `velorix-api` and `velorix-meta`. The product
completion report rejects otherwise valid artifacts when those fields do not
match `VELORIX_RELEASE_COMMIT` and the deployed image digests recorded in
product evidence.

The Hiqlite total-voter-loss drill runner is also fail-closed. It only
validates a produced/provided live evidence JSON for the same no-PVC,
three-voter restore drill represented by either the standalone
`hiqlite_total_voter_loss_restore_drill` kind or the readiness compatibility
evidence kind `hiqlite_no_pvc_three_voter_backup_restore`, and otherwise exits
nonzero with the manual Kubernetes/Hiqlite/RustFS drill boundary. The artifact
must include `deployment_id`, an `s3://` `authority_store_id`, and
the release identity fields plus `evidence_refs` for the object-store backup,
total-voter-loss log, restore log,
acknowledged metadata-write survival proof, and post-restore ingest/query
proof; boolean claims alone are rejected:

```bash
scripts/run-hiqlite-restore-drill.sh --evidence target/velorix-product/hiqlite-restore-drill.json
```

The upgrade/rollback/repair/GC fault-matrix runner is also fail-closed. It only
validates a produced/provided live evidence JSON and otherwise exits nonzero
with the manual release-matrix boundary. The matrix must include GC concurrent
with query, compaction, recovery, and checkpoint publication, and must record
the `deployment_id`, `s3://` `authority_store_id`, and release identity it
validates:

```bash
scripts/run-upgrade-rollback-repair-gc-fault-matrix.sh \
  --evidence target/velorix-product/upgrade-rollback-repair-gc-fault-matrix.json
```

The query output isolation runner is fail-closed. It only validates a live
release artifact proving cold queries read published materialized output, query
pods cannot read source-ingest prefixes or write metadata, and object-store audit
logs show no source reads/writes or durable writes during query. The artifact
must include `evidence_refs` for query pod IAM policy, cold query log,
object-store audit log, and materialized-output read proof, and must record the
`deployment_id`, `s3://` `authority_store_id`, and release identity it
validates; boolean claims alone are rejected:

```bash
scripts/run-query-output-isolation-check.sh \
  --evidence target/velorix-product/query-output-isolation.json
```

The security/release provenance runner is also fail-closed. It only validates a
live/release artifact proving mandatory API and metadata authentication, tenant
authorization, TLS, secret rotation, body limits, rate limits, object-prefix
isolation, negative cross-tenant tests, clean source revision, exact deployed
image digests, SBOM, dependency policy, and immutable test evidence. The
artifact must include the concrete 40-character Velorix `source_revision` and
sha256 `deployed_image_digests` for `velorix-api` and `velorix-meta`, record
the `deployment_id` plus `s3://` `authority_store_id` it validates, plus
`evidence_refs` for auth, TLS, secret rotation, limits, object-prefix
isolation, cross-tenant negative tests, SBOM, dependency policy, and immutable
test evidence; boolean claims alone are rejected. The Hiqlite authority image
digest remains owned by the Hiqlite authority/backend-time attestation gate, not
by this API/meta security provenance helper:

```bash
scripts/run-security-release-provenance-check.sh \
  --evidence target/velorix-product/security-release-provenance.json
```

The remaining release-readiness runner is fail-closed. It only validates a
live/release artifact proving release-image contract tests, versioned OpenAPI
contract consistency, generated fail-closed SQL admission corpus and mutation
coverage, including unsupported plan/expression nodes and proof unsupported SQL
leaves no persisted view metadata or runtime binding, persistent-write crash
consistency, replay determinism, join-frontier
manifest coverage, published limits, and multi-day supported object-store soak.
The artifact must include `evidence_refs` for release-image contract tests,
OpenAPI contract, SQL admission corpus, crash matrix, replay determinism,
join frontier, and scale soak, and must record the `deployment_id` plus
`s3://` `authority_store_id` plus release identity it validates; boolean claims
alone are rejected:

```bash
scripts/run-remaining-release-readiness-check.sh \
  --evidence target/velorix-product/remaining-release-readiness.json
```

For the S3 checkpoint matrix, aggregate already-produced live scenario evidence
with `scripts/run-s3-checkpoint-fault-matrix.sh`. The matrix must include
object write, verification read, manifest write, metadata CAS, delayed
visibility, and retry-after-failure scenarios, and must record the
`deployment_id`, `s3://` `authority_store_id`, and release identity it
validates:

```bash
VELORIX_S3_COMPAT=1 \
AWS_ENDPOINT_URL=... \
AWS_ACCESS_KEY_ID=... \
AWS_SECRET_ACCESS_KEY=... \
AWS_REGION=... \
VELORIX_S3_BUCKET=... \
VELORIX_PRODUCT_DEPLOYMENT_ID=REPLACE_WITH_DEPLOYMENT_ID \
VELORIX_AUTHORITY_STORE_ID=s3://REPLACE_WITH_BUCKET/REPLACE_WITH_PREFIX \
VELORIX_RELEASE_COMMIT=REPLACE_WITH_RELEASE_COMMIT \
VELORIX_API_IMAGE_DIGEST=sha256:REPLACE_WITH_API_DIGEST \
VELORIX_META_IMAGE_DIGEST=sha256:REPLACE_WITH_META_DIGEST \
scripts/run-s3-checkpoint-fault-matrix.sh
```

The runner fails closed when any required scenario evidence file is missing; it
does not synthesize fault-injection results from the compatibility smoke alone.

First-E2E local readiness uses the same evidence shape with
`--first-e2e-artifacts` and intentionally remains below release authority. Its
default product lifecycle output is
`target/velorix-product/ingest-writer-lifecycle-attestation.json`; override it
with `VELORIX_FIRST_E2E_INGEST_WRITER_LIFECYCLE_EVIDENCE` only when reusing a
validated artifact. The RustFS production GC family is kept together:
`target/release-evidence/rustfs-production-gc-seed.json`,
`target/release-evidence/rustfs-production-gc-run.json`, and
`target/release-evidence/rustfs-production-gc-validation.json`; the report must
receive `--rustfs-production-gc-validation-evidence`.

Standing-runtime product evidence must prove the REST relation/create ingest
view/query flow, restart recovery, committed-epoch consistency, fail-closed
admission for unsupported views, `local_api_pod_failover_smoke`, and sibling
`standing-runtime-failover-smoke.json` evidence. For release-grade authority
time, run first-E2E with `VELORIX_FIRST_E2E_PRODUCT_PROFILE=required` and require
`backend_time_source_kind=raft_replicated_authority_time` plus
`production_bounded_failover_safe=true`.

External object-store product-complete evidence may pass
`VELORIX_FIRST_E2E_PRODUCT_OBJECT_STORE_DURABILITY_ATTESTATION_FILE` pointing to
`object-store-durability-attestation.json`; this cannot be used with the
internally generated first-E2E RustFS authority. The non-default RustFS credentials
path is required for first-E2E RustFS evidence, and reusing a RustFS backend with
`VELORIX_FIRST_E2E_SKIP_RUSTFS=1` requires explicit matching S3 credentials.

Ingress evidence can be forwarded with
`VELORIX_FIRST_E2E_PRODUCT_INGRESS_TLS_AUTH_ATTESTATION_FILE`,
`VELORIX_FIRST_E2E_PRODUCT_INGRESS_ENDPOINT_URL`, and related ingress
environment variables. Use `VELORIX_FIRST_E2E_PRODUCT_EVIDENCE_LEVEL=product-complete`
only when `ingress-tls-auth-attestation.json` and the other product-complete
attestations are present.
