## Highlights

- Updates the optional Rhiza backend from 0.19.0 to v0.21.2 and adds a native Local archive mode for metadata authority. Cargo.toml/Cargo.lock now pin the published crate at SHA-256 `c913bfcb9a6c6c6b5340a92c320d08c4941ae07d985e6174de7d59ad12f03db0`.
- Adds local S3-backed archive initialization, recovery, snapshot handling, and graceful shutdown paths, with service and recovery coverage.
- Adds a local Kubernetes deployment template and offline manifest contract. The template is a starting point for isolated qualification; it is not a supported production deployment profile.
- Extends standing-runtime owner authority with explicit reacquisition and authority clock reporting.

## Release policy and gate distinction

The accepted benchmark policy says “Benchmarks are merge and release gates” (`docs/architecture/benchmark-gate-v1.md:6–8`). Its table distinguishes PR smoke—“Ingest, replay, query critical-path changes” on a local object store—from the Release gate, which applies to a “Release candidate,” uses a “Representative S3-compatible backend,” and exists to “Block unsafe releases” (`docs/architecture/benchmark-gate-v1.md:12–16`). PR smoke gates the local result; release gating fails closed without an S3-compatible result or on regression (`docs/architecture/benchmark-gate-v1.md:162–175`). These are distinct obligations. No preview exception is stated.

The repository's PR/main CI is configured on `pull_request` and pushes to `main` (`.github/workflows/ci.yml:3–7`); it is distinct from the manually dispatched `Release Benchmark Gate` workflow (`.github/workflows/release-gate.yml:1–4`). The workflow combines two things: it runs the release S3 benchmark (`.github/workflows/release-gate.yml:217–225`) and validates the 1.0 production-readiness report with release artifacts (`.github/workflows/release-gate.yml:227–290`). It requires both groups of inputs and rejects an architecture critique that still blocks 1.0 (`.github/workflows/release-gate.yml:84–153`). The 1.0 checklist applies its production-readiness certification to commit-bound evidence, S3 benchmark evidence, fault matrices, production GC, query isolation, security provenance, lifecycle/product evidence, and image digests (`docs/release/1.0-readiness-checklist.md:3–22, 69–74`). A passing release benchmark result would satisfy the benchmark requirement only; it would not pass or imply 1.0 production readiness.

**Current release blocker: no in-repository producer for the required fresh S3 release benchmark result was found.** `scripts/run-versitygw-s3-gate.sh` runs S3 storage tests but records that it did not run a benchmark (`scripts/run-versitygw-s3-gate.sh:345–386`). The existing `local_incremental` benchmark is a local-store bench, not an S3 release-result producer (`crates/velorix-runtime/Cargo.toml:26–28`; `crates/velorix-runtime/benches/local_incremental.rs:342`). `scripts/run-first-e2e-readiness.sh` requires a preexisting benchmark result, says the compatibility gate alone does not certify benchmarks, then validates the supplied result (`scripts/run-first-e2e-readiness.sh:354–367`); it also requires production-GC artifacts that the Versity Gateway runner cannot produce while the durable coordinator is unavailable. Do not fabricate or relabel any of these artifacts as a measured release benchmark.

VELORIX_VERSITYGW_RUN_PRODUCTION_GC_EVIDENCE=0 \
VELORIX_VERSITYGW_CARGO_TARGET_DIR="target/versitygw-s3-gate-${CANDIDATE_ID}" \
VELORIX_VERSITYGW_EVIDENCE_PATH="target/release-evidence/versitygw-smoke-${CANDIDATE_ID}.json" \
VELORIX_VERSITYGW_PRODUCTION_GC_SEED_PATH="target/release-evidence/not-produced-seed-${CANDIDATE_ID}.json" \

This runs only the compatibility/crash-restart tests against the runner's local Versity Gateway container. Its output is not a benchmark result, production GC evidence, or release benchmark gate evidence. Cleanup defaults to on; the unique target and evidence paths avoid deleting preexisting results because this script removes its configured output paths before writing.
