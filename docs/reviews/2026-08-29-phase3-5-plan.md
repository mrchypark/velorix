# Velorix Phase 3-5 구현 기획

## ChatGPT Pro 권고 요약

### 1. Write-set/COW 상태 (Phase 3)

**핵심**: 기존 BTreeMap 위에 `EpochOverlay<K,V>` 얇은 transactional 계층 추가

```rust
struct EpochOverlay<'a, K, V> {
    base: &'a BTreeMap<K, V>,
    writes: BTreeMap<K, Write<V>>,
}

enum Write<V> {
    Put(V),
    Delete,
}
```

**읽기 규칙**: write-set → base 순서로 lookup
**기록 규칙**: insert/delete는 write-set에만, get_mut은 key별 lazy clone
**커밋**: validation 완료 후 write-set을 committed map에 적용

**장점**:
- 기존 타입, checkpoint, 대부분의 operator 코드 유지
- full clone만 제거 (checkpoint format 변경 불필요)
- 변경 범위가 가장 작음

**nested state 처리**:
- Temporal join: outer key 단위로 lazy clone
- Cross join: outer key 단위로 lazy clone

### 2. Semi-naive 재귀 (Phase 3)

**핵심**: `all / delta / next_delta` 3-relation 구조

```
all        = 지금까지 확정된 derived rows
delta      = 이번 iteration에서 새로 활성화된 frontier
next_delta = delta로부터 새로 도출된 rows
```

**초기화**: `all = seed, delta = seed`
**iteration**: `candidates = evaluate(delta, all) → next_delta`

**중요사항**:
- `i128` weight가 있으므로 multiset semantics 유지 필요
- `BTreeMap<RowKey, i128>` 기반 deterministic aggregation
- Recursive occurrence별 delta lowering (`delta×all`, `all×delta`)

### 3. 구현 우선순위

```
Phase 1: EpochOverlay<BTreeMap>
  - lazy per-key COW
  - deterministic merged iteration
  - infallible commit boundary
  - 기존 checkpoint 그대로

Phase 2: RecursiveFrontier
  - all / delta / next_delta
  - BTreeMap 기반 deterministic aggregation
  - recursive occurrence별 delta lowering
  - 기존 evaluator와 differential correctness test
```

## 검증 기준

### Write-set/COW
- [ ] state 1M rows, epoch당 100 rows 수정 benchmark
- [ ] epoch 중간 Err 발생 시 committed state byte-for-byte 동일
- [ ] insert/update/delete overlay iterator가 reference BTreeMap과 동일 순서
- [ ] temporal join에서 한 outer key 수정 시 다른 bucket 미clone 확인
- [ ] 기존 checkpoint fixture 호환성

### Recursive frontier
- [ ] chain graph 1→2→...→N transitive closure 정확성
- [ ] diamond/cyclic graph 중복 제거/weight aggregation
- [ ] self-join에서 delta×all, all×delta 중 하나 제거 시 regression
- [ ] 입력 순서 permutation 시 byte-identical output
- [ ] +w, -w 동일 iteration net-zero 전파 방지

## 구현 범위

### 즉시 구현 (중기)
1. `EpochOverlay` 트레이트 + BTreeMap 구현체
2. 모든 runtime에 overlay 적용 (clone-swap → overlay-commit)
3. `RecursiveFrontier` 구조체 + semi-naive evaluation
4. 기존 recursive runtime과 differential correctness test

### 향후 구현 (장기)
- Arrow RecordBatch operator (Phase 4)
- Manifest tree/catalog (Phase 5)
- Reachability GC (Phase 5)
